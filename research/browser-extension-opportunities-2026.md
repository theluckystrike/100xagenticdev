## 2. Revenue Models

### 2.1 Freemium (Dominant Model)
- Core features free, premium at **$4.99-$20/month**
- Most effective for user acquisition -- free tier drives Chrome Web Store rankings
- Typical conversion rate: 2-5% of free users to paid
- Example: **Eightify** -- 100K+ users, **$45K/month** with freemium pricing

### 2.2 Subscription (Monthly/Yearly)
- Best for extensions providing ongoing value or requiring server-side processing
- Especially relevant for AI-powered extensions using LLM APIs
- Typical pricing: **$5-15/month** or **$29-99 lifetime**
- Example: **GMass** -- $8-$20/month plans, **$130K/month** revenue

### 2.3 One-Time Purchase
- Ideal for utility tools with low maintenance costs
- Lower revenue ceiling but simpler to manage
- Example: **CSS Scan** -- $69 one-time, **$100K+ total revenue**

### 2.4 Usage-Based / Credits
- Increasingly popular for AI-powered extensions
- Users buy credits consumed during use
- Aligns costs with actual value delivered
- Example: "User pays $5 for 100 credits rather than $20/month they might not fully use"

### 2.5 Affiliate / Commission-Based
- Extension detects shopping/product contexts and injects affiliate links or coupon codes
- Publisher earns commission on referred sales
- Example: **Honey** -- commission-based model, acquired by PayPal for **$4 billion**
- Example: **Coupert/Pouch** -- earns commission on voucher code purchases

### 2.6 Ethical Data Monetization
- **Mellowtel**: Users opt-in to share unused internet bandwidth; developer gets revenue share
- **Datacy**: Anonymized browsing behavior sold to brands for consumer insights
- Regulatory risk: GDPR, CCPA compliance mandatory
- Must be transparent, opt-in, anonymized, aggregated
- Chrome Web Store policies require explicit disclosure
- Risk of delisting if not properly implemented

### 2.7 Donations / "Acceptable Ads"
- Example: **AdBlock** -- donations + Acceptable Ads program, estimated **$3.7M/month** (~$44M/year)
- Works only at massive scale (65M+ users)

## 8. Technical Requirements

### Manifest V3 (Mandatory as of 2026)
- MV2 extensions disabled everywhere since Jul 2025
- MV2 support fully removed in Chrome 139
- **Key constraints**:
  - No remotely-hosted code -- all code must be in extension package
  - `declarativeNetRequest` API replaces `webRequest` (30K rule limit)
  - Background logic runs in service workers (wake/sleep lifecycle)
  - Stricter Content Security Policy

### Development Stack
- **Languages**: JavaScript/TypeScript (primary), HTML, CSS
- **Frameworks**: React, Vue, Svelte all work for popup/options UIs
- **Build tools**: Webpack, Vite, Plasmo (extension-specific framework)
- **Testing**: Jest, Playwright for E2E
- **Payment processing**: ExtensionPay, Dodo Payments, Stripe, LemonSqueezy

### Cross-Browser Compatibility
- WebExtensions API is largely compatible across Chrome, Firefox, Edge
- Firefox still supports MV2 AND MV3 (competitive advantage for ad-blocking type extensions)
- Edge extensions are Chrome-compatible with minimal changes

### Infrastructure Costs
- Pure client-side extensions: near-zero ongoing cost
- AI-powered extensions: LLM API costs (OpenAI, Anthropic, etc.) -- must be passed to users via subscription/credits
- Backend services: minimal for most extensions ($5-50/month VPS)

## 10. Risks

### Manifest V3 Restrictions
- **30K rule limit** kills complex ad-blocking approaches
- Service worker lifecycle (sleep/wake) can cause state management bugs
- No remote code execution limits dynamic feature delivery
- **Mitigation**: Design around constraints from the start; most extensions are unaffected

### Chrome Web Store Policy Risks
- **40%+ rejection rate** for non-compliant submissions
- Broad permission requests (like `<all_urls>`) trigger rejection -- must request minimum permissions
- Google may remove extensions without clear explanation
- April 2026: surge in submissions causing extended review times
- **Mitigation**: Minimal permissions, clear privacy policy, verified developer domain

### Platform Risk
- Google owns the distribution channel -- can change rules at any time
- Extension can be delisted for policy violations (sometimes arbitrary)
- Chrome Web Store is a monopoly for Chrome users
- **Mitigation**: Cross-browser support (Firefox, Edge), maintain direct user relationships (email list), have a web app fallback

### Competition Risk
- AI is lowering barriers to entry -- more extensions being created faster
- 38,015 new Chrome extensions added in Q1 2026 alone
- **Mitigation**: Focus on niches, build brand/community, ship faster with AI

### Data/Privacy Regulatory Risk
- GDPR, CCPA compliance mandatory for data monetization
- Chrome Web Store policies increasingly strict on data collection
- **Mitigation**: Minimize data collection, be transparent, use opt-in consent
